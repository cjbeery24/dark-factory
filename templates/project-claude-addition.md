## Dark Factory — Specification-Driven Development

This project uses the **Dark Factory** pipeline for specification-driven development with enforced information barriers between AI agents.

### Critical Rules — NEVER Violate

1. **NEVER read `.dark-factory/holdouts/` when implementing code.** These contain adversarial blind holdouts generated by the QA Holdout agent. Reading them invalidates the entire testing process. If you are writing or modifying implementation code, you MUST NOT read, reference, or reason about any file in `.dark-factory/holdouts/`. VIOLATIONS INVALIDATE THE PIPELINE RUN. The Implementer **is** allowed and expected to read visible AC-aligned tests under `.dark-factory/scenarios/` — those are the Test Engineer's output and serve as the TDD signal the Implementer iterates against.

2. **NEVER read implementation source code when generating tests or holdouts.** Both the Test Engineer (visible tests) and the QA Holdout agent (adversarial holdouts) must derive their output purely from the specification. They MUST NOT read source files in `__SOURCE_DIR__/`. VIOLATIONS INVALIDATE THE PIPELINE RUN.

3. **All non-trivial changes MUST start with a validated specification** in `.dark-factory/specs/`.

4. **Quality gates are mandatory.** Code does not ship until it passes blind scenarios and review.

### Agent Quick Reference

| Role | You Read | You NEVER Read | What You Do |
|------|----------|----------------|-------------|
| Spec Validator | `.dark-factory/specs/` | — | Validate spec completeness |
| Implementer | Validated spec, source code, `.dark-factory/scenarios/` (visible tests) | `.dark-factory/holdouts/` | Write code that passes the visible tests |
| Test Engineer | Validated spec, architect manifest, `environment.toml`, project manifest (package.json, etc.) | Source code (`__SOURCE_DIR__/`), `.dark-factory/holdouts/` | Write AC-aligned **executable** tests in the project's native test framework |
| QA Holdout | Validated spec, architect manifest | Source code (`__SOURCE_DIR__/`), `.dark-factory/scenarios/` | Generate adversarial blind holdouts |
| Reviewer | Spec, code, test results | — | Evaluate quality |
| Oracle | Everything | — | Ship/no-ship decision |

### Directory Structure

```
.dark-factory/
├── specs/       → Specifications (input to pipeline)
├── scenarios/   → Blind test scenarios (RESTRICTED)
├── reviews/     → Review outputs
├── reports/     → Quality gate reports
├── audit/       → Audit logs (agent activity, barrier violation detection)
├── state/       → Pipeline state files (for resume/recovery)
├── plans/       → Project plans (decomposed into specs)
└── config.toml  → Project-specific toolchain config
```

### Running the Pipeline

```bash
# Full pipeline (validates spec → generates scenarios → implements → tests → reviews)
dark-factory run <spec-name>

# Individual steps
dark-factory validate <spec-name>
dark-factory gate <spec-name>
dark-factory scenarios <spec-name>
```
