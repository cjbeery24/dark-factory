# Skill: Write Specification

## Trigger
User wants to write a new specification.

## Behavior

1. Ask the user what type of spec they need:
   - Feature → use `templates/feature-spec.md`
   - Bug fix → use `templates/bug-fix-spec.md`
   - API endpoint → use `templates/api-spec.md`
   - Refactoring → use `templates/refactor-spec.md`
   - Database migration → use `templates/db-migration-spec.md`
   - Integration → use `templates/integration-spec.md`
   - Performance optimization → use `templates/performance-spec.md`
   - Security fix → use `templates/security-fix-spec.md`

2. Read the selected template.

3. If the spec has **Status: STUB** (generated by `/df-write-plan`):
   - Read the stub and identify pre-filled sections (Problem Statement, NFRs, Constraints, Dependencies, Out of Scope)
   - Confirm the pre-filled content with the user — adjust if needed, but don't re-interview for information already present
   - Focus the interview on placeholder sections only: Functional Requirements, Interface Contract, Edge Cases, Error Handling, Acceptance Criteria, Examples
   - When complete, change Status from STUB to DRAFT

4. Interview the user to fill in each section. For each section:
   - Explain what information is needed
   - Ask targeted questions to extract the details
   - Push back on vague answers: "Can you be more specific about what 'fast' means? What latency target in milliseconds?"
   - Suggest edge cases they may not have considered
   - Suggest error conditions they may have missed

5. Write the completed spec to `.dark-factory/specs/[YYYY-MM-DD]-[name].md`

6. Run the spec through mental validation against the completeness checklist:
   - Every section filled in?
   - No weasel words?
   - All types defined?
   - All edge cases enumerated?
   - All errors handled?
   - At least 2 examples?

7. **Precision Analysis awareness:** The spec will be subjected to a Precision Analysis (Implementation Divergence Test) during validation, where the validator sketches 3 maximally-different implementations. If those sketches diverge on specified behavior (HIGH divergence), the spec will be blocked. Write the spec precisely enough that two independent readers would build the same externally observable behavior.

8. If gaps remain, point them out and help the user fill them.

## Output
A complete specification file ready for formal validation.

## Key Phrases
- "write a spec", "create a spec", "new specification"
- "I want to build...", "I need to implement..."
- "spec for [feature]"
