## Changes from v2

### Showstoppers Fixed

1. **Quality Gate container now uses `:rw` mount** — v2 used `:ro` which would break all build commands (`npm run build`, `cargo build`, etc.) that write to the project tree. QG now gets full read-write access since it's not an LLM agent and has no barrier requirements.

2. **Scenario Architect source barrier now masks multiple directories** — New `SOURCE_DIRS` config variable (space-separated list) replaces single `SOURCE_DIR` for barrier purposes. Masks `src`, `lib`, `app`, `components`, `pages`, or whatever the project configures. Fixes H4 from v1 evaluation.

3. **Oracle agent definition updated alongside parser** — v2 only fixed the parsing code but left `oracle.md` specifying markdown headers on line 1. Now both the agent definition and the parser agree: plain `SHIP` or `NO-SHIP` on line 1.

### Moderate Issues Fixed

4. **Prompt barriers (`--disallowedTools`, `--append-system-prompt`) are KEPT** — v2 removed them. They're now retained as zero-cost defense-in-depth inside containers.

5. **Per-role cache volumes** prevent cache poisoning — Implementer uses `df-impl-npm-cache`, QG uses `df-qg-npm-cache`. A malicious Implementer can't poison the QG's npm cache with postinstall scripts.

6. **Symlink safety check** added — Pre-flight scan before barrier agents detects symlinks crossing barrier boundaries and aborts with a clear error.

7. **`--read-only` rootfs removed** — Claude Code may write to arbitrary paths. Rather than chasing every writable path with tmpfs, we rely on container ephemerality (`--rm`) and dropped capabilities.

8. **Container cleanup trap** — `cleanup_containers()` kills orphaned containers from the pipeline run on crash/SIGKILL.

9. **Debug mode (`--debug`)** — Keeps containers alive on failure for `docker exec -it` inspection.

10. **Explicit `:rw` on all override mounts** — v2 relied on Docker's default. Now explicit for clarity.

11. **Container names** — Each container gets a predictable name (`df-{spec}-{role}-{pid}`) for audit logging and cleanup.

12. **`run_quality_gate()` uses `--workdir /workspace`** and resolves the quality gate script path via `DARK_FACTORY_HOME`.

13. **Migration guide** added to implementation order — `docs/MIGRATION.md` for existing installations.

14. **Docker licensing note** added to documentation plan — Docker Desktop vs Docker Engine distinction.

15. **Audit logging** now captures container names, images, and mount configurations.

### Known Limitations (Documented, Accepted)

- Network egress unrestricted (hardening opportunity, not default)
- Reviewer can leak scenario details in feedback text (data flow problem, not filesystem)
- No iteration rollback/snapshots
- Hardlinks could theoretically bypass tmpfs masking (extremely unlikely)
- Pre-existing issues M5, M6, M7 not addressed
